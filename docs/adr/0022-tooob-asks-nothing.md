# tooob asks nothing; it says what to type

Supersedes the guided `tooob share` of #22. No `tooob` command asks a question, in a terminal or not: when something it needs is missing, it says what in one line and shows the command as typed with a placeholder in the gap, ready to edit (a missing Host Name lists the Hosts there are). A terminal and a script get the same behaviour, so `tooob share PATH --relay URL --invite NAME` is one shot that can be backgrounded, and Agents, which can't answer prompts, use the same commands people do. Where a person used to be asked about what a folder holds, `share` warns in one line instead and carries on: a `.git` (a repository's whole history), `.env` or `.ssh` anywhere inside it, or the whole home folder. It refuses nothing, so there's no flag to get past it (amended 2026-10-30: the first version refused `.git` unless `--include-git`).

We rejected keeping the questions for people at a keyboard. A command that asks in one setting and not another has two behaviours to learn and test, a backgrounded job that asks a question is stopped by the shell without a word, and a question loop ("Who else?") gets between an Owner and a one-liner. Guided set-up for Normal people belongs in the tray app, not the command line.
