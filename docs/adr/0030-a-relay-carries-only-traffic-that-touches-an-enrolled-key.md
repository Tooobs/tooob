# A Relay carries only traffic that touches an Enrolled Key

Settled by the Owner on 2026-11-07 (#98), amending ADR 0020. A Relay's address is public: it's in every Invite Link, and r.tooobs.net's is in this repo's issues. Anyone running iroh can point a client at it and use its bandwidth for traffic that isn't the Relay Operator's, and that open Relay is also what makes a hosted one look like a general proxy (`docs/research/cloudflare-free-relay.md`). So a Relay now carries traffic only for keys its Relay Operator has enrolled: it forwards a packet only if its sender or its receiver is an Enrolled Key. Visitors' browsers connect exactly as before, with no credential and nothing new in the Invite Link: their packets reach an Enrolled Host because the receiver is enrolled, and the Host's replies go back because the sender is. Two strangers can connect, but nothing passes between them. Who may see a Site is unchanged: the Host checks every Visitor itself (ADRs 0002, 0011), and a Relay can still only deny, never admit.

Stock iroh-relay checks a client once, when it connects, and has no hook where it forwards a packet; its `http` access mode sees only the connecting key. So a Relay runs `tooob-relay`, a binary of tooob's own: iroh-relay's server built from a fork pinned at the version tooob uses, with a small patch where `Clients::send_packet` already has both keys in hand (about three files and fifty lines), and that hook offered upstream to n0 so the fork can go. It replaces n0's prebuilt binary in the Relay image (ADR 0020 stays one container) and `iroh-relay --dev` in the tests.

An Owner gets a Host enrolled with an Enrollment Code: the Relay Operator makes one (`tooob-relay code --label sam`), it names its Relay (`r.tooobs.net/7Q4K-M2XD-9PHT-WB3C`), and `tooob add NAME TARGET --relay-code CODE` (or `share`, or `tooob enroll NAME CODE` for a Host already made) presents it as `?token=` on the Host's first relay connection. `tooob-relay`'s access check sees the code and the Host Key iroh's handshake has just proven, enrolls that key and uses the code up, so nobody can redeem a code for a key they don't hold. A code is about 80 bits, is stored only hashed, enrolls one Host and expires unused after 7 days unless made with `--uses N` or longer; a client that gets several codes wrong is refused for a while. A refused code leaves nothing behind: `add` removes the Host it made. A Relay Operator can also enroll a key by hand (`tooob-relay enroll <key> --label photos`), for their own Hosts.

## Considered and rejected

- **Stock iroh-relay's `allowlist` of Host Keys.** It shuts out every Visitor's browser, since each tab connects with a fresh key (ADR 0011).
- **A shared token.** A browser could only send one from the Bootstrap, which is public.
- **Admitting browsers by their WebSocket `Origin`** (an Enrolled Host's Key Address). Any non-browser client can set it, and a Site's own JavaScript on its Key Address can open Relay connections with it. It's a speed bump, not a rule.
- **A short-lived relay credential signed by the Host for each Visitor**, carried in the Invite Link (the TURN REST pattern). It's sound, but it changes what browsers do and adds a refresh for returning Visitors, which the forwarding rule makes unnecessary.
- **Enrolling by hand only.** It means the Owner sending the Relay Operator a 52-character key, and the Relay Operator editing a file, for every Host.

## Consequences

- The list of Enrolled Keys and Enrollment Codes is one file on the Relay's `/data` volume, which survives redeploys on Fly and a VPS. `tooob-relay` watches it, so a change applies within a second, and removing a key disconnects it at once.
- A Relay with no Enrolled Keys is open, as every Relay was before, and says so in its log at every start and in `/__tooob/relay.json` (`{"relay_access": "open"}` or `"enrolled"`; not in `version.json`, the Bundle's manifest, whose hash identifies the Bundle); its first enrollment closes it. Upgrading cuts off no Host, and the deploy wizard enrolls the Relay Operator's first Host Key, so a new Relay starts closed.
- An unenrolled Host's packets are dropped without a word, so the Relay answers `GET /__tooob/enrolled/<key>`, which tells nothing a Key Address doesn't already show. `tooob add`, `run`, and every 10 minutes while running, ask it and say when the Host isn't enrolled, with the Host Key to give the Relay Operator, as the Bootstrap check does (ADR 0020).
- Relay admin: `tooob-relay` commands to make, list and cancel codes and to enroll, label, list and remove keys, run in the container (`fly ssh console -C …`); then a basic admin page (#133) that logs in with an Operator Token (ADR 0031), so it is safe on whatever network reaches it. A tunnel is the recommended way in (`fly proxy`, `ssh -L`), and it is never on the Relay's public address: `tooob-relay` serves it on `[::]:8081` in the container, never routed through the front (Caddy), with no Fly `[[services]]` entry; on a VPS, Compose publishes it on `127.0.0.1` only. Nothing in the Relay depends on Fly.
- Not decided here: limits per Enrolled Key, and how Relay finder (#72) lists a Relay as open or closed.
